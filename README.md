# 研发供应商资源平台（原型）

面向研发工程师的**设备加工厂 / 构配件供应商**资源平台原型。单文件零依赖 HTML，双击即用，也可直接部署在任意静态空间。

## 在线地址

https://qutyler.github.io/rd-supplier-platform/

扫码链接前缀默认已指向上述地址，无需手动配置。若部署到你自己的地址，在「需求详情 → 扫码链接前缀」里改一次即可（存 localStorage）。

## 三大功能

| 功能 | 说明 |
| --- | --- |
| 需求发布 | 整机定制 / 构配件集成，填写构件清单（构件、规格、数量、参考单价、小计），自动算合价。图纸附件非必填 |
| 智能匹配 | 四档判定：R1 能力边界（唯一硬门槛）→ R2 接单意愿 → R3 资质 → R4 预算（单值心理价位）。结果：推荐 / 可联系 / 不符 / 待确认 |
| 询价比价 | 需求生成询价二维码 → 微信转发 → 供应商手机扫码填构件报价 → 回传码粘贴导入 → 到手总价排序 + 构件逐项比价 |

附：供应商库（P7）自动沉淀「推荐 / 可联系」的厂家，跨需求累加接触记录，可导出 CSV。

## 为什么二维码能直接扫出表格

原型没有后端，研发电脑上新建的需求，手机端是取不到的。解决办法是把需求内容压进二维码链接（`?x=…`）：

1. 链接自带数据 —— 手机扫码时用链接里的数据渲染，直接出构件报价表；
2. 构件过多、二维码装不下时 —— 导出独立 `invite.html`，发给供应商；
3. 供应商提交后 —— 生成 `RDQ1.` 开头的回传码，研发在「询价比价」页粘贴即可入库。

真正有了后端之后，第 2、3 步可以省掉，供应商提交即直接入库。

## 本地继续开发

源文件是仓库根目录的 `index.html`，全部逻辑（数据、路由、二维码编码器、打包压缩、导出页）都在这一份文件里，改完直接替换即可。

验证脚本（jsdom）位于另一份交付包中，期望结果：

```
node tests/verify_lib.js      43 项通过
node tests/verify_scan.js     29 项通过
node tests/verify_invite.js   40 项通过
node tests/verify_budget.js   27 项通过
```
